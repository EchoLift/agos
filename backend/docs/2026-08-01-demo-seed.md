# 2026-08-01 Demo Seed System

## Purpose

`seed:demo` creates one realistic AGENCIE demo tenant for local product testing.

The dataset is intentionally narrative, not random. It covers the rolling window from 15 days before the run date through 15 days after the run date, so dashboard, campaign, workflow, calendar, notification, team and client screens all have useful states.

## Commands

Run from `backend/`:

```bash
npm run seed:demo
npm run seed:demo:reset
```

Both commands are idempotent. They delete and recreate only the demo tenant with slug `socialexpert`.

The seed requires the normal backend encryption environment:

- `DATABASE_URL`
- `FIELD_LOOKUP_SECRET`
- `ENCRYPTION_SECRET` or `FIELD_ENCRYPTION_KEY_BASE64`

## Data Ownership

The seed reuses the existing Prisma schema and writes through required foreign keys:

```text
Agency
  -> Memberships
  -> Clients
  -> Campaigns
  -> Campaign Deliverables
  -> Content Assets
  -> Workflow Instances
  -> Workflow Tasks
  -> Submissions / Approvals / Blockers
  -> Publishing Schedules
  -> Notifications / Deliveries
  -> Outbox / Audit Events
```

The Workflow Engine remains the production source of truth. The Calendar is populated from workflow task deadlines and publishing schedules, so sync-sensitive pages can be tested against the same data.

## Reset Safety

The reset deletes only records belonging to the `socialexpert` agency, plus the fixed demo auth users listed above. It does not wipe other agencies, users, clients, campaigns or workflow data.
