# Phase 1: Auth Module Implementation Design

Date: July 20, 2026

## Overview

The Auth Module is the first domain-specific module to be implemented. Every other module depends on identity, making this the foundation of all business logic. 

**Scope**: Identity only. 
**Out of Scope**: Permissions, Agencies, Memberships, Roles. (These belong to Phase 3. Auth guards belong to Phase 4).

## Core Requirements

Based on the [Implementation Order](2026-07-20-implementation-order.md), this module will implement:
- `/register`
- `/login`
- `/refresh`
- `/logout`
- Session persistence
- Password hashing

### Security Features
- **Password Hashing**: Argon2id
- **Password Policy**: Minimum 12 characters, Maximum 128 characters, no truncation, Unicode allowed. (No arbitrary composition rules like uppercase/lowercase/numbers required).
- **Email Encryption**: AES-256 (PII must be encrypted at rest in `AuthUser.emailEncrypted`).
- **Email Lookup**: HMAC-SHA256(email, FIELD_LOOKUP_SECRET). Blind index in `AuthUser.emailHash` to allow unique constraints and fast lookups without decrypting, protected against rainbow tables.
- **Access Tokens**: Short-lived JWT returned in response body.
- **Refresh Tokens**: Long-lived 256-bit random opaque string stored in an `HttpOnly`, `Secure` cookie. (Not a JWT).
- **Session Management**: Each login creates a `Session` record in the database tracking metadata like `lastRotatedAt`, `createdByIp`, and `createdByUserAgent` alongside current values.
- **Refresh Token Rotation**: Each refresh invalidates the previous refresh token and issues a new one. `refreshTokenFamilyId` tracks token families to detect reuse.
- **Token Reuse Detection**: If a reused/revoked token is detected, revoke the entire token family and force login again.
- **Rate Limiting**: `POST /login` allows 5 attempts / minute per IP + per emailHash. (Handled by the Gateway layer, but documented here).

## Database Schema (Prisma)

The module will interact with the following existing models:

- `AuthUser`: Stores `emailEncrypted`, `emailHash`, `passwordHash`, and `status`.
- `Session`: Tracks active sessions, linking `authUserId` with `refreshTokenHash` and `refreshTokenFamilyId`. Also tracks `deviceLabel`, `userAgent`, and `ipAddressEncrypted` for audit and security purposes.

## API Endpoints

### 1. Register (`POST /api/v1/auth/register`)
- **Body**: `{ "email": "...", "password": "..." }`
- **Action (Transactional)**: 
  1. Hash email with HMAC-SHA256.
  2. Encrypt email for storage with AES-256.
  3. Hash password with Argon2id.
  4. Create `AuthUser` record.
  5. Create `OutboxEvent` for `UserRegistered`.
  6. Commit transaction.
- **Response**: `{ "success": true, "message": "User registered" }` (No auto-login on register to keep flows explicit).

### 2. Login (`POST /api/v1/auth/login`)
- **Body**: `{ "email": "...", "password": "...", "deviceLabel"?: "..." }`
- **Action**:
  - Hash provided email with HMAC to find `AuthUser`.
  - Verify password against Argon2id hash.
  - (On failure of either step: Return `401 Unauthorized`. Do not enumerate accounts).
  - Generate JWT Access Token.
  - Generate 256-bit random string Refresh Token.
  - Create `Session` record storing the hash of the Refresh Token, and metadata.
  - Create `OutboxEvent` for login audit.
  - Set HttpOnly cookie for Refresh Token.
- **Response**: `{ "accessToken": "eyJ...", "expiresIn": 900 }`

### 3. Refresh (`POST /api/v1/auth/refresh`)
- **Cookies**: Requires `refreshToken`
- **Action**:
  - Extract token from cookie.
  - Hash token and look up active `Session`.
  - **Token Reuse Detection**: If the session is already revoked or token doesn't match the active family tip, revoke ALL sessions in that family and return 401.
  - Generate new Access Token.
  - Generate new 256-bit Refresh Token (Rotate).
  - Update `Session` with new refresh token hash and `lastRotatedAt`.
  - Create `OutboxEvent` for refresh audit.
  - Set new HttpOnly cookie.
- **Response**: `{ "accessToken": "eyJ...", "expiresIn": 900 }`

### 4. Logout (`POST /api/v1/auth/logout`)
- **Cookies**: Requires `refreshToken`
- **Action**:
  - Look up `Session` and mark status as `REVOKED`.
  - Create `OutboxEvent` for logout audit.
  - Clear HttpOnly cookie.
- **Response**: `{ "success": true }`

### `UserRegistered`
```json
{
  "eventType": "UserRegistered",
  "authUserId": "...",
  "emailHash": "...",
  "occurredAt": "...",

```
*(Never include `emailEncrypted` or `passwordHash` in events)*.
