# AGENCIE Mobile Experience Phase 1

Date: 2026-08-12

## Objective

Make AGENCIE usable as an operational product on phones without replacing or weakening the existing desktop experience. Mobile uses the same APIs, tenant context, permissions, and workflow commands as desktop.

## Shared Components Affected

- `WorkspaceHeader`: compact responsive header, search trigger, profile and workspace switcher.
- `MobileWorkspaceNav`: role-aware bottom navigation, quick create, and overflow menu.
- `GlobalSearch`: active-workspace command palette for pages and authorized resources.
- Workspace layout: compact content gutter, safe-area bottom clearance, and full-width operational layout.
- Status styles and existing API clients are reused; no mobile-only business rules are introduced.

## Interaction Patterns

### Navigation

- Desktop keeps the horizontal role-aware navigation.
- Mobile uses a compact bottom navigation with a permission-aware create action.
- Lower-frequency destinations move into a full-width `More` sheet.
- Profile and workspace switching remain available from the header.

### Search

- Desktop opens search with `Cmd+K` or `Ctrl+K` and also exposes a header trigger.
- Mobile opens a full-screen search sheet from the header or bottom navigation.
- Results are grouped into pages, clients, campaigns, content, workflow, gigs, people, and help.
- The active agency is always the search scope.
- Resource requests use existing tenant-scoped APIs. Results are never produced from records a normal API request cannot return.
- V1 filters bounded API results in the client. A dedicated permission-aware backend search endpoint is the scale-up path.

### My Work

- Metrics become a compact two-column mobile grid.
- Work remains a single task queue generated by existing operational projections.
- Desktop keeps its richer split layout.

### Workflow

- Desktop keeps the stage board.
- Mobile presents stage selectors and a vertically scanned task list.
- The detail drawer becomes a full-screen mobile surface.
- Workflow submissions and reviews use the same workflow command API.
- Relevant action controls stay above the bottom navigation on phones.
- Edit controls are visible only to Owner, Admin, and Manager roles; the backend remains authoritative.

### Gigs

- List filters collapse on phones.
- Cards expose the assignee, due date, status, and direct open action without a table.
- Submission and review controls remain touch-safe and sticky where needed.

### Calendar

- Agenda is the default mobile representation.
- Day, week, month, and year views remain available from tablet widths.
- Day and week time grids initially scroll to 09:00 instead of midnight.
- Role scope and visible-calendar preferences continue to use the existing backend and UI state.

## Desktop Behaviors That Do Not Collapse Directly

- The workflow Kanban board becomes a stage-filtered list on phones.
- The calendar canvas becomes an agenda on phones.
- Right-side workflow details become full-screen.
- Dense filter rows become compact disclosures or stacked controls.
- Tables are not converted globally in this phase; priority operational routes use cards where required.

## Responsive Constraints

- Mobile: below 640px.
- Tablet: 640px through 1023px.
- Desktop: 1024px and above.
- Minimum practical touch target: 44px.
- No required hover interaction.
- No intentional page-level horizontal overflow.
- Operational spacing defaults to `p-3`, `p-4`, `gap-2`, and `gap-3`.
- Safe-area padding is applied to fixed bottom navigation and sticky actions.

## Explicit Deferrals

- Campaign and client creation are not converted into multi-step mobile forms in Phase 1.
- Campaign detail receives no unrelated desktop redesign.
- Client portal navigation and approvals are not implemented because the client portal is not currently complete.
- A full notification center is not created in this phase.
- No global backend search endpoint, fuzzy index, AI commands, or cross-workspace search is added.
- No drag-and-drop calendar or workflow interaction is added on mobile.
- No backend business behavior is changed.
