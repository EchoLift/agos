## What This Is

Reviews and approvals control how work moves between people and production stages.

Depending on the workflow, a team member may submit work, review a handover, approve work, request changes, or return work to the previous stage.

The actions available to you depend on your role, assignment, and the current workflow stage.

## Script Review

When a writer completes a script and submits it for review, the responsible reviewer can:

- Approve the script
- Request changes

Approving allows the content to move toward the next production stage.

Requesting changes returns the work to the writer with feedback so it can be revised and submitted again.

## Production Handover

Work can also move directly between production roles.

For example:

Writer
→ Script review
→ DOP
→ Editor
→ Edit review
→ Ready for publishing

The exact stages depend on the workflow configured for the content.

## Editor Intake

When footage is handed over from the DOP, the assigned editor can review the handover.

The editor can:

- Accept the handover
- Reject the handover with a reason

Accepting allows editing work to begin.

Rejecting returns the handover to the DOP so the issue can be resolved before editing continues.

## Edit Review

When an editor submits a draft or final output, the responsible reviewer can review the submission.

Depending on the workflow, the reviewer can:

- Approve the work
- Request changes

Requested changes return the work to the appropriate production stage.

Approval allows the content to continue toward completion and publishing.

## Requesting Changes

When requesting changes, explain what needs to be corrected.

Useful feedback should tell the previous owner what needs to change before the work can move forward.

Instead of:

> Fix this.

Prefer:

> Reduce the opening section and replace the final shot with the approved product close-up.

The workflow should make responsibility clear rather than forcing the team to reconstruct feedback from chat messages.

## Resubmitting Work

When changes are requested, responsibility returns to the appropriate production owner.

After making the requested changes:

1. Open the returned work.
2. Review the feedback.
3. Update the work or external submission.
4. Add useful notes about what changed.
5. Submit the work again.

The work returns to the appropriate review stage.

This revision cycle can continue until the work is approved.

## Assignment And Permissions

Being able to view a workflow does not automatically allow a user to approve or reject its work.

Available actions depend on:

- The current workflow stage
- The user's role
- The user's assignment
- The action allowed at that stage

This prevents unrelated team members from moving production work they do not own or review.

## What Happens After Approval

Approval moves the work to the next configured stage.

Depending on the workflow, this may mean:

- Assigning the next production task
- Moving from writing to shooting
- Moving from shooting to editing
- Moving work into another review stage
- Marking content ready for publishing

AGENCIE keeps the workflow state connected to the underlying content so the team can see where production currently stands.

> [!TIP] Keep Feedback In The Workflow
> When requesting changes or rejecting a handover, include the reason in AGENCIE so the next person knows exactly what needs to happen.
