## Best First Test

The easiest way to understand AGENCIE is to run one real piece of content through the complete production flow.

Start small:

Client
→ Campaign
→ Publishing Slot
→ Content
→ Workflow
→ Production
→ Review
→ Ready for Publishing

This shows how planning, assignments, deadlines, and production connect without setting up an entire month's content first.

## Before You Start

For the most useful test, make sure you already have:

- A business client
- At least one production team member
- A campaign
- The relevant campaign team
- A publishing plan

Use real team assignments where possible so each person can see how AGENCIE behaves from their own workspace.

## Create The Content

1. Open the client's campaign.
2. Add a publishing slot for one piece of content.
3. Set the relevant platform, date, time, and content details.
4. Generate production from the publishing slot.
5. AGENCIE creates the corresponding content and starts its production workflow.

The publishing plan now becomes actual production work rather than remaining only a scheduled commitment.

## Follow The Workflow

Open the generated work in **Workflow**.

You can see:

- The current production stage
- The current owner
- Deadline
- Client and campaign context
- Available actions
- Previous workflow activity

The assigned team member can then complete the action required at that stage.

Depending on the configured workflow, the content can move through stages such as:

Writing
→ Script Review
→ Shoot
→ Editor Intake
→ Editing
→ Edit Review
→ Ready for Publishing

The exact stages and assignments depend on the workflow and production setup.

## Check Each View

As the content moves through production, check the different operational views.

**Workflow**
→ Shows where the content currently is and what should happen next.

**My Work**
→ Shows work directly assigned to the current user.

**Calendar**
→ Shows relevant scheduled work and deadlines.

**Campaign**
→ Keeps the content connected to the larger client plan and publishing commitment.

These are different views of the same operational work rather than separate copies of it.

## Complete The Test

For your first test, try moving one content item through several production stages using the actual users responsible for those stages.

For example:

1. Assign writing work.
2. Submit the completed work.
3. Review it.
4. Request changes once to test the return flow.
5. Resubmit and approve it.
6. Continue to the next production stage.
7. Check My Work and Calendar from the assigned user's account.

This is also a useful way to verify that role permissions and assignments behave correctly before running real client production.

## When To Use A Gig Instead

Not every piece of work needs a campaign.

Use a **Campaign** when the work belongs to a structured client plan with deliverables, dates, production, and publishing.

Use a **Gig** when you need a smaller direct assignment without building a complete campaign plan.

> [!TIP] Test One Item First
> Before setting up an entire month of client content, run one item through the workflow. Once your team understands the handoffs and assignments, scale the same process to the rest of the campaign.

> [!WARNING] Do Not Use A Campaign For Every Small Request
> If you only need a small standalone assignment, such as five scripts by Friday, a Gig is usually faster than creating a complete campaign and publishing plan.
